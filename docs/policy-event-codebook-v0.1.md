# 政策事件编码手册 v0.1

## 纳入标准

- 必须来自央行、政府或法定监管机构的官方原文。
- 必须改变政策操作目标、利率形成、传导机制或金融稳定框架，而非普通例行操作。
- 必须能确定公开日期，并写明为什么该事件会改变制度比较。

## 字段

- `event_date`：官方公布或生效日。
- `category`：利率框架、操作目标、政策传导、收益率曲线框架等受控类别。
- `direction`：对机制变化的描述性编码，不表示好坏，也不直接映射分数。
- `coding_reason`：一到两句可审计理由。
- `source_url`：支持该编码的官方原文。
- `reviewers`：不同角色的复核标识；同一角色重复出现只计一次。

## 审批规则

- 单个事件至少需要两个不同复核人。
- 第二复核人不能只检查链接可访问性，还要检查类别、方向和理由。
- 每国至少两条双人批准事件、至少两个共同可比类别，政策分数才可解锁。
- 退回事件不得删除；后续版本需保留原状态与退回理由。

## 禁止事项

- 不根据市场涨跌反推政策事件方向。
- 不把政策宽松或收紧直接解释为经济结果好坏。
- 不因缺少第四个结构分项而降低审批门槛。
- 不让人工政策判断直接修改情景概率。
